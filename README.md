# Java Project Matching App

Javaの自己学習で習得した内容を使って開発している、案件マッチングアプリです。

案件情報とエンジニアの保有スキル・経験年数・希望条件を比較し、
案件ごとのマッチスコアを確認できます。

Java基礎で作成した **Ver0.1 コンソール版** を土台に、
現在はメソッド、オブジェクト指向、コレクション、例外処理、パッケージ分割などを反映した
**Ver0.2へのリファクタリング** を進めています。

> 本アプリで使用している案件情報は、学習用に作成した架空のサンプルデータです。

---

## 制作目的

Javaの自己学習で学んだ内容を実際のアプリケーション開発へ適用し、
基礎構文だけでなく、クラス設計や責務分離について理解を深めることを目的として制作しています。

最初から完成形のWebアプリを作るのではなく、

```text
Ver0.1
Java基礎によるコンソール版
↓
Ver0.2
メソッド・オブジェクト指向などを反映したJava版
↓
Ver1.0
Webアプリ版
```

のように、Javaの学習段階に合わせて同じアプリを段階的に発展させています。

完成を急ぐことよりも、

- 学習した内容を実際のコードへ反映する
- 実装した処理を自分の言葉で説明できる
- 既存機能を維持しながら段階的に改善する

ことを重視しています。

## 各クラスの役割

### Main

アプリケーションの起動とコンソール操作を担当します。

主な役割：

- サンプル案件の作成
- エンジニア情報の作成
- メニュー表示
- ユーザー入力受付
- 案件一覧表示
- 必須スキル検索
- リモート可能案件表示
- マッチスコア表示

---

### Project

1件の案件情報を管理します。

保持する情報：

- 案件名
- 案件スキル一覧
- 勤務地
- リモート可否

案件に設定されているスキルは、

```java
List<ProjectSkill>
```

として管理しています。

---

### ProjectSkill

案件に設定される1つのスキル条件を管理します。

保持する情報：

- スキル名
- 必須 / 尚可
- 必要実務経験年数

必須・尚可は定数で管理しています。

```java
public static final int REQUIRED = 1;
public static final int OPTIONAL = 2;
```

---

### Engineer

1人のエンジニア情報を管理します。

保持する情報：

- 希望勤務地
- リモート希望
- 保有スキル一覧

保有スキルは、

```java
List<Skill>
```

として管理しています。

---

### Skill

エンジニアが保有する1つのスキルについて管理します。

保持する情報：

- スキル名
- 経験区分
- 実務経験年数

経験区分は定数で管理しています。

```java
public static final int LEARNING_ONLY = 1;
public static final int PRACTICAL_EXPERIENCE = 2;
```

---

### MatchCalculator

案件情報とエンジニア情報を比較し、
マッチスコアとマッチレベルを算出します。

スコア計算処理を `Main` から分離することで、

```text
Main
→ 入力・表示

MatchCalculator
→ マッチング処理
```

のように役割を分けています。

## マッチスコア

案件ごとに最大100点で計算します。

| 評価項目 | 最大点 |
|---|---:|
| 必須スキル＋経験年数 | 50点 |
| 尚可スキル | 30点 |
| 勤務地 | 10点 |
| リモート条件 | 10点 |
| 合計 | 100点 |

---

## 必須スキル＋経験年数

各必須スキルについて、エンジニアの経験状況から係数を算出します。

| エンジニアの状態 | 係数 |
|---|---:|
| スキルなし | 0.0 |
| 学習経験のみ | 0.5 |
| 実務経験あり・必要年数指定なし | 1.0 |
| 実務経験あり・必要年数指定あり | 経験年数に応じて計算 |

必要実務経験年数が指定されている場合は、

```text
0.5 + 0.5 × (実務経験年数 ÷ 必要経験年数)
```

で係数を計算します。

係数の上限は `1.0` とします。

例えば案件条件が、

```text
Java 実務3年以上
```

の場合、

```text
スキルなし     → 0.0
学習経験のみ   → 0.5
実務1年        → 約0.6667
実務2年        → 約0.8333
実務3年以上    → 1.0
```

となります。

複数の必須スキルがある場合は、

```text
必須スキル点
= 必須スキルの係数合計
  ÷ 必須スキル数
  × 50
```

で計算します。

必須スキル数が増えても、最大点は50点です。

---

## 尚可スキル

尚可スキルは以下の係数を使用します。

| エンジニアの状態 | 係数 |
|---|---:|
| 実務経験あり | 1.0 |
| 学習経験のみ | 0.5 |
| スキルなし | 0.0 |

複数の尚可スキルがある場合は、

```text
尚可スキル点
= 尚可スキルの係数合計
  ÷ 尚可スキル数
  × 30
```

で計算します。

例えば、

```text
Linux       → 実務経験あり → 1.0
Java        → 学習のみ     → 0.5
Spring Boot → スキルなし   → 0.0
```

の場合、

```text
(1.0 + 0.5 + 0.0) ÷ 3 × 30
= 15点
```

となります。

尚可スキルが0件の場合は0点とし、
30点を他の評価項目へ再配分しません。

---

## 勤務地

エンジニアの希望勤務地と案件勤務地が一致する場合、

```text
10点
```

を加算します。

一致しない場合は0点です。

---

## リモート条件

現在のコンソール版では、
エンジニアがリモート勤務を希望している場合、

```text
案件がリモート対応 → 10点
案件がリモート不可 → 0点
```

としています。

リモート勤務を希望していない場合は、
案件条件にかかわらず10点としています。

---

## 小数の扱い

マッチスコアの途中計算では `double` を使用しています。

途中では小数を切り捨てず、
すべての項目を合計した後に、

```java
Math.round()
```

を使用して整数へ四捨五入します。

---

## マッチレベル

最終スコアに応じて以下の3段階で判定します。

| スコア | 判定 |
|---|---|
| 80〜100点 | 高マッチ |
| 60〜79点 | 候補 |
| 0〜59点 | 低マッチ |

## 学習したこと・振り返り

### 平行配列からオブジェクト管理への変更

Ver0.1では、
案件情報やエンジニアのスキル情報を複数の配列で管理していました。

オブジェクト指向を学習した後、

```text
平行配列
↓
Project / Engineer / Skill / ProjectSkill
```

へ変更しました。

これにより、
関連するデータを1つのオブジェクトとして扱えるようになり、
データ同士の関係を把握しやすくなりました。

---

### Listを利用した複数スキル対応

当初は1案件につき、

```text
必須スキル1件
尚可スキル1件
```

という構造でした。

現在は `Project` が、

```java
List<ProjectSkill>
```

を保持する構造へ変更し、

```text
必須スキル複数件
尚可スキル複数件
```

を扱えるようにしています。

スキル数が増えてもスコアの最大値が変わらないよう、
各スキルの係数の平均から点数を計算する方式に変更しました。

---

### 経験年数を含むマッチング

以前は、

```text
必須スキル
経験年数
```

を別々の評価項目として加点していました。

現在は、
必須スキルの経験区分と必要実務経験年数を組み合わせて評価しています。

これにより、

```text
学習経験のみ
実務経験あり
実務経験はあるが必要年数に不足
必要年数を満たしている
```

という状態を分けて評価できるようになりました。

---

### クラスとパッケージの責務分離

当初は `Main` に多くの処理が集中していました。

現在は、

```text
Main
→ アプリの起動・入力・表示

model
→ データ管理

MatchCalculator
→ マッチング計算
```

のように役割を分けています。

さらに、

```text
app
model
service
```

のパッケージへ分割することで、
ファイル数が増えた場合でも役割を把握しやすい構成へ変更しました。
